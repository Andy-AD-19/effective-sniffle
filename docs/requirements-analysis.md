# Requirements Analysis

## Functional Scope

The system manages institutional stock from master data registration through receipt, inspection, storage, issuance, monitoring, physical counting, reconciliation, disposal, and reporting. Both fixed assets and consumable stock are supported, with batch and expiry tracking used where applicable.

## Core Entities

- Users, roles, permissions, departments, approval requests, audit logs.
- Items, categories, units of measure, funding sources, suppliers/donors, store locations, shelves, bins.
- Goods receiving notes with multiple lines, inspection decisions, rejected quantities and reasons.
- Stock ledger entries as the append-only source of truth for receipts, issues, adjustments, disposals, and transfers.
- Issue requests and store issue vouchers.
- Physical inventory cycles, count worksheets, count lines, adjustment approvals.
- Disposal requests, committee review records, disposal actions.
- Report exports and query parameters.

## Workflows

1. Master data is configured, then active items become available for receiving and requesting.
2. A GRN is created from procurement, donation, allocation, or project support. Lines are inspected independently. Accepted quantities post receipt ledger entries; rejected quantities remain reportable.
3. Storage metadata and generated barcode values are tied to accepted stock batches.
4. Departments request stock. Approvers approve or reject. Approval creates a store issue voucher and posts negative ledger entries against automatically selected batches.
5. FIFO is used for general items; FEFO is used for perishable or expiry-tracked items.
6. Physical counts compare counted quantities to ledger-derived system balances. Variances require approval before adjustment entries post.
7. Disposal follows identification, review, approval, action recording, and ledger deduction.
8. Reports are generated server-side as PDF or Excel with filters.

## Edge Cases Covered

- Partial receipts: GRN line quantity received can be partially accepted and partially rejected.
- Rejected quantities: stored on inspection lines with mandatory reasons.
- Backordered issuance: MVP hard-blocks issuance beyond available stock; override can be added through a permission-gated approval path.
- Negative stock prevention: ledger posting service validates availability before issue, adjustment-out, or disposal.
- Expired batches: FEFO allocation excludes expired batches for issue; reports surface expired balances.
- Soft deletion: referenced master data is deactivated, not hard deleted.
- Adjustment integrity: balances are changed only by approved ledger transactions.

## Assumptions

- Item code may be supplied manually, otherwise generated by the API.
- A batch is represented by item plus batch number plus expiry date plus location metadata.
- Fixed assets can use quantity `1` stock units initially; serial-level custody can be added later.
- MVP report files are generated synchronously; a background job queue can be introduced once exports become large.
- LAN deployment uses Docker Compose with PostgreSQL; the same containers can be deployed to a VPS with environment changes.
